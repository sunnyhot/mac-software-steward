## 目标
在 `brew upgrade --cask` 之前，自动用 GitHub 镜像（ghproxy）预下载 cask 文件到 brew 的缓存目录。brew 发现缓存文件后跳过下载，直接安装。预下载失败则静默跳过，不影响原有流程。

## 技术基础（已验证）
- brew 缓存文件名 = `SHA256(downloadURL)` (完整 64 位 hex) + `--` + URL basename
- cask 的 URL 和 sha256 可从 `brew info --cask --json=v2` 获取（`HomebrewCaskDownloadSizeResolver.caskURL` 已实现 URL 提取）
- brew 缓存目录：`~/Library/Caches/Homebrew/downloads/`
- ghproxy 镜像格式：`https://mirror.ghproxy.com/<原URL>`（GitHub Releases 的 URL）

## 新增文件：CaskMirrorPrefetcher.swift
轻量预下载器，纯函数风格，不依赖 AcceleratedDownloader 的复杂状态机：

```
enum CaskMirrorPrefetcher {
    struct CaskDownloadInfo { var url: URL; var sha256: String }

    // 1. 从 cask name 解析下载 URL + sha256（复用 brew info --cask --json=v2）
    static func resolveDownloadInfo(caskName:..., brewPath:...) async -> CaskDownloadInfo?

    // 2. 判断是否需要镜像（仅 github.com/release/download 的 URL）
    static func mirrorURL(for url: URL) -> URL?
    // github.com/... → mirror.ghproxy.com/github.com/...

    // 3. 预下载：URLSession 下载镜像 URL → 临时文件 → 校验 sha256 → 移到 brew 缓存
    static func prefetch(info: CaskDownloadInfo, onProgress:...) async -> Bool
    // 返回 true=缓存已就绪，false=跳过（任何失败都静默跳过）
}
```

关键逻辑：
- **SHA256 校验**：下载后计算文件 sha256，与 cask 声明的 sha256 比对。不匹配则删除临时文件、返回 false（不让错误缓存进 brew）
- **缓存已存在则跳过**：如果 brew 缓存目录已有目标文件，不重复下载
- **仅 GitHub URL 走镜像**：非 GitHub URL（如 1password.com 直连）不走镜像——这些不一定慢，且镜像不一定支持
- **镜像 URL 构造**：`https://mirror.ghproxy.com/<原完整URL>`

## 集成点：MaintenanceExecutor.swift
在 `runPackageStepsConcurrently` 的 `launchNext()` 里，`runCommand` 之前，对 cask step 做预下载：

```
group.addTask {
    // 预下载（仅 cask，formula/mas 跳过）
    if caskName = step.caskName {
        await prefetchCask(jobID: id, step: step, caskName: caskName, token: token)
    }
    let result = await executor.runCommand(...)
    ...
}
```

`prefetchCask` 是 MaintenanceExecutor 的私有方法：
- 调 `CaskMirrorPrefetcher.resolveDownloadInfo` 拿 URL + sha256
- 调 `CaskMirrorPrefetcher.prefetch` 下载
- 进度通过 `appendLog` + `updatePackageDetail` 反馈到 UI（"正在通过镜像预下载..."）
- 失败静默（记日志"镜像预下载失败，使用默认下载"）

## UpgradeStep 需暴露 cask name
当前 `UpgradeStep` 有 `packageID` 和 `packageName`，但 cask name 需要从 package 解析。在 step 构建处（`upgradeSelectedPlanRows` / `upgrade`）cask name 就是 `packageName`。或者在 `runCommand` 前从 `step` 拿。确认 step 是否携带足够信息。

## 进度反馈
预下载时在 UI 显示：
- "正在通过镜像预下载 {caskName}（{百分比}%）"
- 通过 `updatePackageDetail` 更新 `phaseText` = "镜像预下载"，`downloadFraction` 更新百分比
- 预下载完成后 phaseText 变回正常（brew 接管安装）

## 不改的部分
- `AcceleratedDownloader` 不改（它服务 app 自更新，机制独立）
- brew 命令参数不改（仍 `brew upgrade --cask --greedy name`）
- `DownloadAccelerationStrategy` 代理重试机制不改（预下载和代理重试是两个独立加速层，不冲突）
- formula / mas 升级不预下载（只有 cask 的 GitHub URL 需要镜像）

## 错误处理（安全第一）
| 场景 | 行为 |
|---|---|
| 镜像服务不可用/超时 | 静默跳过，brew 正常下载 |
| sha256 不匹配 | 删除临时文件，静默跳过 |
| brew 缓存已有文件 | 跳过预下载（brew 也会跳过） |
| 非 GitHub URL | 不走镜像 |
| 用户取消（token cancelled） | 中止预下载，正常退出 |

**核心安全保证**：预下载**绝不阻塞或破坏**原有升级流程。任何失败都 fallback 到 brew 默认下载。
