# 项目清理与重构计划

## 原则
- **零行为变更**：纯机械删除/移动/提取，不改变任何运行时逻辑。每个可编译单元改完后能 `swiftc` 通过。
- **每步可验证**：每个阶段结束跑 `npm test`，全部通过才进入下一阶段。
- **按用户决策收敛范围**：不动下载加速（命名/文案/本地代理探测）、不重命名 Inbox、MaintenanceExecutor 只保守提取 2 组、历史文档归档。

## 阶段 B — 保守拆分 MaintenanceExecutor（提取 2 个无状态组）

子代理分析确认两组**无实例状态、无 host 依赖**，可纯机械提取。提取成 `MaintenanceExecutor` 持有的内嵌 namespace，**保持 public surface 名不变**（StewardModel 调用 `executor.command(...)`、测试访问 `model.executor.packageProgress` 都不受影响）。

### B1. 提取「命令解析」组（Group H, 行 853-889）
- 新建 `native/MacSoftwareSteward/MaintenanceCommandResolver.swift`，放 `enum MaintenanceCommandResolver`，含静态方法 `command(for:includeGreedy:)`、`requireCommand(_:)`、`validateBrewToken(_:)`（原方法体逐字搬）。
- `MaintenanceExecutor` 保留同名实例方法作为**转发包装**（`func command(...) throws { try MaintenanceCommandResolver.command(...) }`），或直接让调用方改用 `MaintenanceCommandResolver`——**优先转发包装**，因为 StewardModel.swift:234/349/358/388 通过 `executor.command(...)` 调用，转发可零改调用方。
- 更新 `scripts/build-native.sh`：新文件在 `native/MacSoftwareSteward/*.swift` glob 内，主 app 自动包含；**Agent 不需要**（Agent 不调升级命令解析），无需改显式列表。`StewardModelScanGuardTest` 通过 glob 不拉单文件——但 `test-native.sh:369+` 的该测试显式列了 `MaintenanceExecutor.swift`，需**加** `MaintenanceCommandResolver.swift` 到该 `run_test` 块（因为 MaintenanceExecutor.swift 现在引用它）。

### B2. 提取「失败分析」组（Group I, 行 1185-1252）
- 同文件已有 `struct FailureAnalysis`（行 1257-1263，已在 Supporting types 段）。把 `failureAnalysis(command:code:output:)` 和 `firstErrorLine(in:)` 提取到 `enum MaintenanceFailureAnalyzer`。
- 同样用转发包装或直接调用。
- 更新 `test-native.sh` 的 `StewardModelScanGuardTest` 块，加入新文件（若采用新文件）。

### B3. 同步构建脚本（关键）
- 主 app（`build-native.sh:68`）用 glob，新增 `.swift` 文件自动包含——**无需改**。
- Agent（`build-native.sh:76-97`）显式列表：确认这两个新文件 Agent 不需要（Agent 只做 `daily-check` 扫描+自动升级，走 `MaintenanceExecutor.upgrade` 但 Agent 编译单元不含 `MaintenanceExecutor.swift`——已验证 Agent 显式列表里没有它）→ **无需改 Agent**。
- `test-native.sh` 的 `StewardModelScanGuardTest`（行 369-411）显式列了 `MaintenanceExecutor.swift`：**必须加入**两个新文件，否则该测试编译失败（MaintenanceExecutor 引用了它们）。
- 其他单文件测试若引用被提取方法→逐一检查（预期无，因为只有 StewardModelScanGuardTest 和大型编译单元含 MaintenanceExecutor）。

**预期结果**：MaintenanceExecutor.swift 从 1275 行降到约 1050 行，零行为变更。
